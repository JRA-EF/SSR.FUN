# Launchpad provenance for Reserve assets

Which Solana launchpad a catalogue token was created on, whether it is still on its bonding curve, and where its liquidity trades after graduation. Added 2026-09-18 (see `docs/project/DECISION_LOG.md`, DEC-0206).

**Scope.** Provenance is a label. It never makes a token eligible as a Reserve asset and it never bypasses the catalogue's existing gates: Jupiter's verified list (weekly snapshot), the Token-2022 exclusion, one mint per symbol, the reserved USDC symbol, and the `ssr_status` review flag (`api/ledger/asset-catalogue.ts`). A supported launchpad is not a safety rating.

**Detection is on-chain only.** A token is attributed to a launchpad only when an account that *only the launch program can create* exists for that mint, owned by that program, with the expected Anchor discriminator, and, where the launch program is shared by several platforms, carrying the platform's own verified identity. Names, symbols, metadata URIs, mint-address suffixes (`…pump`, `…bonk`, `…BAGS`), API labels and website domains are never inputs.

Code: `packages/sdk/src/launchpads.ts` (identifiers, decoders, `classifyLaunchpad`, `detectLaunchpad`, `classifyMintsBatch`), `lib/ledger/launchpadClassification.ts` (catalogue job), `api/ledger/launchpad-classify-cron.ts` (daily cron), `src/merge/lib/launchpadLabels.ts` (wording, filter). Tests: `tests/phase_launchpads.ts`.

Why these identities cannot be imitated:

- Only the pump program can create an account owned by itself at the bonding-curve PDA. A PumpSwap pool alone proves nothing: anyone can open a PumpSwap pool for any mint, so the venue is accepted only for the canonical pool whose creator is the pump program's own pool-authority PDA.
- LaunchLab is shared by many platforms; LetsBONK is identified by its PlatformConfig account, which on-chain carries the name `letsbonk.fun` and web `https://letsbonk.fun/` (offsets 112 and 176 of the 944-byte PlatformConfig, discriminator `[160,78,128,0,248,83,230,160]`). Community CPMM pools for the same mint are ignored: only the pool created by LaunchLab's authority PDA is the migration venue (8,784 such pools existed on 2026-09-18).
- DBC is shared by many partners; Bags is identified by the `creator` of the virtual pool, a signer the DBC program requires at creation, so nobody without Bags's key can produce it. On 2026-09-18 Bags's authority was the creator of 204,549 DBC pools (154,447 distinct configs, roughly one per token, so config or fee-claimer addresses are **not** a stable identity), and the update authority of the Bags token metadata.

## Catalogue integration

- Columns on `ledger_asset_catalogue` (`scripts/migrate-launchpads.mjs`, `lib/ledger/schema.sql`): `launchpad`, `launchpad_stage`, `launchpad_venue`, `launchpad_evidence` (the proving accounts), `launchpad_checked_at`. `checked_at` null = never classified; non-null with `launchpad` null = verified as not from a supported launchpad.
- `api/ledger/launchpad-classify-cron.ts` runs daily (`vercel.json`, `middleware.ts` CRON_PATHS), bounded to 400 mints per run: never-checked first, then bonding-stage tokens older than 2 days (they can graduate), then anything older than 30 days. RPC failures leave a mint unclassified rather than recording "not a launchpad". Pause with `LAUNCHPAD_DETECTION_ENABLED=false`.
- `api/ledger/asset-catalogue.ts` returns `launchpad: { id, stage, venue } | null` per token; the gates it applies are unchanged.
- The Launch Reserve asset picker (`src/merge/pages/CreateDTR.tsx`) shows a badge ("Pump.fun · PumpSwap", "LetsBONK.fun · bonding", …) and a "Launched on" filter (Any origin / Pump.fun / LetsBONK.fun / Bags.fm / Not from a launchpad). The filter only narrows the list.

## Limitations and open points

- **Pre-March-2025 Pump.fun graduations** migrated to Raydium AMM v4. They are reported as graduated with an unknown venue (no canonical PumpSwap pool); the AMM v4 pool is not derived.
- **LaunchLab AMM v4 migrations** (`migrate_type` 0) report the venue by type only; the pool is not derived.
- **Bags venue coverage**: about 6% of migrated Bags pools in the sample had neither DAMM metadata PDA; those show as graduated with an unknown venue.
- **Token-2022 launchpad tokens** (possible on LaunchLab and DBC) remain excluded from the picker by the pre-existing Token-2022 rule regardless of provenance.
- **Not a security check.** The catalogue does not verify mint authority, freeze authority, Token-2022 extensions, liquidity depth or sell routes at listing time, before or after this change; sell routes are exercised at trade time by the Jupiter-backed sell flow. Launchpad provenance adds no such check and must not be read as one.
- **Identity constants can rotate.** LetsBONK's PlatformConfig and Bags's launch authority are single accounts controlled by those teams; if either platform rotates them, new launches stop being attributed until the constant is updated (existing labels persist). The daily re-check window bounds the staleness of stage/venue.
- **RPC cost.** Per-mint on-demand detection of a non-launchpad token costs a 6–10 s DBC program scan; the catalogue job avoids this with one scan of Bags-created pools per run (`classifyMintsBatch`). Do not call `detectLaunchpad` per token from the browser.
